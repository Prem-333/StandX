# Standards metadata acquisition plan

Checked 20–21 September 2026. This phase captures **20 individual BIS public metadata pages**, four per procurement domain, then adds 130 visibly synthetic editions. It archives only metadata HTML, not standard PDFs. Every captured URL and timestamp is in [SOURCES.md](SOURCES.md) and the corresponding `data/raw/bis/*.provenance.json`. Field text is HTML-decoded with layout whitespace collapsed; original bytes are preserved and hashed. Spelling errors, encoding defects, empty values, contradictory equivalent-standard labels, and unresolved references are retained for review. Domain assignments are project curation, separate from BIS's taxonomy.

## Access and feed findings

Direct requests for `services.bis.gov.in/robots.txt`, its `www` redirect host, and `www.manakonline.in/robots.txt` returned HTTP 404. The web tool also failed to retrieve those policies. The [BIS terms](https://www.bis.gov.in/terms-and-conditions/?lang=en) were reviewed; they require independent verification of ambiguous information and distinguish linked-site policies. No portal-specific automated harvesting permission was established. The [e-BIS public landing page](https://www.manakonline.in/MANAK/login) did not establish a bulk metadata export route. These observations do **not** grant crawl or redistribution rights.

Bounded searches of BIS, NIC, and data.gov.in found no verified, documented public bulk standards catalogue API. OGD results concerned [BIS enforcement statistics](https://delhi.data.gov.in/resource/firm-wise-enforcement-activity-outlets-selling-toys-without-bureau-indian-standards-bis-0) and institutional counts, rather than the required standard-level dataset. A BIS XML-conversion procurement excerpt mentions internal APIs; that is not an offered public feed. This is a search finding, not proof of non-existence. Bulk-feed availability and automation permission remain **unverified — confirm before relying on this**. Ask BIS/ITSD about an official metadata service before designing an integration around undocumented endpoints.

## Replacement after the hackathon

**A. Licensed bulk agreement — preferred.** Obtain written BIS authorization defining metadata fields, catalogue identifiers, amendment/revision history, reference direction and semantics, taxonomy exports, update delivery, permissible local embeddings, retention, attribution, redistribution, and air-gapped use. Request an initial signed/checksummed snapshot plus changed/deleted-record feeds, withdrawal and effective-date information. Full standards text is excluded unless independently licensed and explicitly supplied. Stage imports, compare changes, quarantine conflicts, obtain curator sign-off, and publish a versioned KB release with rollback artifacts.

**B. Scheduled metadata collector — conditional fallback.** Implement only after BIS confirms an acceptable arrangement and applicable terms. Recheck robots and terms before runs; stop on denial, unavailable policy, authentication barriers, or revoked authorization. Allowlist metadata pages and fields; exclude PDFs, purchase/download links, personal details, and session data. Use a single worker, an agreed request budget/delay, conditional requests where supported, exponential backoff, and immediate suspension on 403/429. Prefer announced changes over catalogue rescans. No such live collector is implemented in this repository.

**C. Curated taxonomy and evidence.** Have a BIS-informed domain reviewer maintain versioned Group → Sub-group → Sub-sub-group paths and the separate Aspect facet. Keep source labels alongside any search synonyms. Review malformed references, ambiguous supersession, and certification flags; never infer mandatory certification from catalogue wording alone. Resolve requirements against separately verified legal instruments and effective dates.

**Proposed cadence, subject to agreement:** ingest an official amendment/change feed daily if available; otherwise perform an agreed weekly metadata delta refresh, a monthly curator review of exceptions/taxonomy, and a quarterly reconciliation. These are project operating targets, not claimed BIS publication schedules. Urgent withdrawal or mandatory-rule changes trigger review when notified. Air-gapped deployments receive signed, scanned update bundles on an approved weekly transfer cycle and always display the snapshot date and stale-data limitations.
