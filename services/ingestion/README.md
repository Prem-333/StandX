# Metadata ingestion

`python -m services.ingestion.load INPUT` uses `DATABASE_URL` and the isolated `kb` PostgreSQL schema. Inputs are a JSON array of records or CSV with a `record_json` column containing each complete JSON object; the extra CSV `is_number` and `source` columns are inspection aids. Nested classifications, amendments, schemes, and references stay lossless. See `data/processed/standards_seed.json` and its CSV counterpart for executable examples.

Imports run in one transaction under an advisory lock. Stable record IDs and edition identifiers are unique. Repeated input does not duplicate rows. A newer observation replaces current metadata and reconciles its children; older observations remain in `source_snapshot` without rolling current data back. Changed input creates another immutable content-addressed snapshot. The loader recomputes each family's latest observed pointer, explicit superseded flags, and resolution of references imported in earlier batches. Cyclic/ambiguous supersession rejects the entire transaction. This phase does not assert that the newest observed year is the latest BIS publication.

`source_snapshot` retains the original imported record; `revision` stores queryable scalar fields. Classification is normalized into hierarchy/facet nodes and revision links. Raw certification flags are separate from evidenced scheme requirements. Real scheme requirements and individual amendment dates are unknown in this sample. Cross-reference endpoints are directional and can remain unresolved, without fabricated Standard rows.

`python -m services.ingestion.validate --output data/processed/validation_report.json` reports missing classifications, orphan Indian references, malformed international identifiers, and supersession cycles/branches. `--strict` fails on all findings; default mode fails on supersession conflicts and reports incomplete-corpus warnings. `parse_snapshot.py` only parses local HTML; there is no network collector. All source text is preserved in raw snapshots, with HTML entities decoded and layout whitespace collapsed in normalized values.

`npm run phase2-demo` exercises SQL using an isolated PGlite engine with PostgreSQL wire protocol. It tests JSON/CSV idempotency, changed children, stale imports, and atomic cycle rejection. PGlite is a development verification aid, not a substitute for production PostgreSQL operational testing.
